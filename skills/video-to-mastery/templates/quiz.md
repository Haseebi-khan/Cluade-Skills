# Knowledge Check

Close most modes (except Quick) with a short knowledge check drawn from the essential/important content just taught. Mix question types rather than using all of one kind:

- A **conceptual** question ("why does X happen?")
- A **practical/implementation** question ("which approach should you use today, and why?")
- A **debugging or "fix this"** question, when there's code/config/commands involved
- An **"explain in your own words"** question for the core mental model

Example shape:

```markdown
## Knowledge Check

1. Why does <X> happen? (conceptual)
2. What would happen if <Y> changed? (transfer)
3. Which approach should you use today — <old> or <new> — and why? (currency check)
4. Here's a snippet using the old approach: `<code>` — what needs to change? (debugging)
5. Explain <core concept> in your own words. (mental model check)
```

Keep it to 3–5 questions for standard/deep mode, 1 for quick mode if included at all. Don't reveal answers immediately — let the user attempt them first, and offer to check their answers if they respond with attempts. If they ask for answers up front, give them, but note they'll learn more by trying first.
